Ormo includes an optional app for Astro's development toolbar. It scans rendered Ormo primitives, reports common semantic and accessibility mistakes, and lets you jump to the element that needs attention.

The toolbar currently checks [Accordion](/docs/components/accordion), [Button](/docs/components/button), [Dialog](/docs/components/dialog), [Alert Dialog](/docs/components/alert-dialog), [Popover](/docs/components/popover), [Tooltip](/docs/components/tooltip), and related primitives. It complements each component's console diagnostics and will expand as Ormo adds primitives. It only runs through Astro's development toolbar and adds nothing to production pages.

## Setup

Import the integration from its independent package entry point and add it to the Astro configuration:

<CodeBlock
  lang="js"
  code={`import { defineConfig } from "astro/config";
import ormoDevToolbar from "@ormo/primitives/dev-toolbar";

export default defineConfig({
  integrations: [ormoDevToolbar()],
});`}
/>

Start the Astro development server and select Ormo in the toolbar. A warning indicator appears when the current page contains a detected issue.

For a page packed with intentional Accordion mistakes, open the [Accordion toolbar demo](/docs/dev-toolbar/accordion-demo).

## Checks

The initial checks include:

- Buttons without an accessible name
- Positive <code>tabindex</code> values
- Interactive elements nested inside a Button
- Accordions with no Item parts
- Accordion Items missing a non-empty <code>value</code>
- Duplicate Accordion Item values in the same root
- Accordion Items missing a Trigger or Content part
- Accordion Triggers without an accessible name
- Alert Dialog roots with missing or multiple Content parts
- Alert Dialogs without an accessible name, description, or response control
- Detached Alert Dialog Triggers with a missing or invalid Root target
- Dialog roots with missing or multiple Content parts
- Dialogs without an accessible name or visible Close control
- Detached Dialog Triggers with a missing or invalid Root target
- Invalid or unavailable <code>finalFocus</code> destinations

The scanner reruns when the rendered DOM changes and after Astro client-router navigation. These checks catch common structural mistakes, but they do not replace keyboard and screen-reader testing.

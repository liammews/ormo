## Anatomy

Compose `Radio` with `RadioIndicator` for a custom appearance. Place the indicator after the radio under the same label, and give every member a unique value:

<CodeBlock
  lang="astro"
  code={`---
import { Radio, RadioIndicator } from "@ormo/primitives/radio";
import * as RadioGroup from "@ormo/primitives/radio/group";
---

<RadioGroup.Root name="delivery" defaultValue="standard">
  <RadioGroup.Label>Delivery speed</RadioGroup.Label>

<label>
  <Radio class="radio" value="standard" />
  <RadioIndicator class="radio-indicator">
    <span class="radio-dot"></span>
  </RadioIndicator>
  Standard
</label>

  <label>
    <Radio class="radio" value="express" />
    <RadioIndicator class="radio-indicator">
      <span class="radio-dot"></span>
    </RadioIndicator>
    Express
  </label>
</RadioGroup.Root>`}
/>

`RadioGroup.Root` supplies the shared name that gives native radios their single-selection and keyboard behaviour. `RadioIndicator` is hidden from assistive technology and does not intercept pointer input.

Use [Fieldset](/docs/components/fieldset) instead when radios only need native semantic grouping. `RadioGroup.Root` is the enhanced option for live group properties, value events, DOM control, or [Field](/docs/components/field) integration.

### Required group

Set `required` on `RadioGroup.Root` when one option must be selected. Ormo applies native `required` state to the members, so form submission, `checkValidity()`, `reportValidity()`, `novalidate`, and `formnovalidate` retain browser behaviour.

Wrap the group in `Field.Root` to connect descriptions and visible errors to the group. Use `RadioGroup.Label`, rather than `Field.Label`, for its accessible name.

`ormo:value-change` fires after a member selection or `value` property assignment changes the selected value. It bubbles across shadow boundaries, cannot be cancelled, and exposes the updated `value` and a `reason` of `"member"` or `"programmatic"` in `event.detail`. Assigning the current value does not emit an event, and property assignment does not synthesise native `input` or `change` events.

<CodeBlock
  lang="js"
  code={`const group = document.querySelector("ormo-radio-group");

group.addEventListener("ormo:value-change", (event) => {
console.log(event.detail.value);
console.log(event.detail.reason);
});

group.value = "express";
group.disabled = true;`}
/>

## Accessibility

`Radio` uses native radio semantics, checked and disabled exposure, focus, keyboard interaction, validation, and form participation. Every member needs an accessible name that includes its visible label. Prefer a wrapping `<label>` or a sibling `<label for="…">`.

`RadioGroup.Root` follows the [WAI-ARIA Radio Group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/). It uses `role="radiogroup"` and an accessible name supplied by `RadioGroup.Label`, `aria-label`, or `aria-labelledby`. The members must share one non-empty name for the browser’s native single-selection, focus, and arrow-key behaviour.

When no radio is selected, <kbd>Tab</kbd> generally focuses the first enabled member. When a value is selected, the checked member is the group’s Tab stop. Exact initial focus direction can follow browser and platform conventions.

## Styling

Radio ships no layout or brand styles. The recommended custom composition uses `appearance: none` on the native input and places `RadioIndicator` over it. Use native pseudo-classes for state and a general-sibling selector (`~`) for the indicator. Leave native appearance intact when the operating-system radio is preferred.

`RadioIndicator` includes only a low-specificity `pointer-events: none` rule so a decorative overlay cannot steal input. Attributes prefixed with `data-ormo-*` are internal runtime selectors, not styling APIs.

## Runtime

A standalone `Radio` renders only a native input and ships no production JavaScript. `RadioIndicator` adds one behaviour-critical CSS rule but no production JavaScript. `RadioGroup.Root` loads a small custom-element runtime for live names, disabled and required inheritance, generated label maintenance, group value events, and the browser API.

Server rendering already applies member names, the default value, disabled and required state, and accessible label relationships. Without JavaScript, same-name members retain native single selection, focus, arrow-key interaction, validation, form reset, and submission; only live group property changes, generated-label updates, group events, and the custom-element API are unavailable.

## Anatomy

Compose `Checkbox` with `CheckboxIndicator` for a custom appearance. Place the indicator after the checkbox inside a native label so the input retains its native semantics, interaction, and form behaviour:

<CodeBlock
  lang="astro"
  code={`---
import { Checkbox, CheckboxIndicator } from "@ormo/primitives/checkbox";
---

<label>
  <Checkbox class="checkbox" name="terms" />
  <CheckboxIndicator class="checkbox-indicator">
    <svg viewBox="0 0 16 16" aria-hidden="true">
      <path d="M3 8.5 6.5 12 13 4" />
    </svg>
  </CheckboxIndicator>
  Accept the terms and conditions
</label>`}
/>

`CheckboxIndicator` is hidden from assistive technology and does not intercept pointer input. Use the native input’s `:checked` and `:indeterminate` pseudo-classes with a general-sibling selector (`~`) to control its presentation. The general-sibling selector remains reliable when development tooling inserts non-rendering elements between the parts.

Import the group separately when checkboxes need shared value state, parent selection, or at-least-one validation:

<CodeBlock
  lang="astro"
  code={`---
import { Checkbox } from "@ormo/primitives/checkbox";
import * as CheckboxGroup from "@ormo/primitives/checkbox/group";
---

<CheckboxGroup.Root name="protocols" defaultValue={["https"]}>
  <CheckboxGroup.Label>Allowed protocols</CheckboxGroup.Label>
  <label><Checkbox value="http" /> HTTP</label>
  <label><Checkbox value="https" /> HTTPS</label>
</CheckboxGroup.Root>`}
/>

Use [Fieldset](/docs/components/fieldset) instead when controls only need native semantic grouping. `CheckboxGroup.Root` is the enhanced option for coordinated behaviour.

## Examples

### Native checkbox

Omit `CheckboxIndicator` and do not remove the input’s native appearance when the operating-system checkbox is preferred. This is the smallest rendering path and ships no component CSS or JavaScript for a binary checkbox.

### Indeterminate

Set `indeterminate` for an initially mixed checkbox. Mixed state is a DOM property, so Ormo applies it with a small client runtime. Native activation then clears the mixed state and toggles the checkbox normally.

An indeterminate checkbox cannot also receive the `checked` prop. Change its state after rendering through the native `checked` and `indeterminate` properties.

### Checkbox group

`CheckboxGroup.Root` gives member checkboxes a shared name, applies `defaultValue` during server rendering, and exposes the current selected values through its browser API. An explicitly authored member `name` takes precedence over the group name.

  files={[{ filename: "Checkbox.astro", code: checkboxGroupDemoCode }]}

### Parent checkbox

Add `parent` to one checkbox inside a group to control all enabled members. The parent becomes indeterminate when some, but not all, members are checked. It does not submit a name or value.

Disabled members retain their state when the parent is activated. Nested parent-checkbox trees are not supported.

  files={[{ filename: "Checkbox.astro", code: checkboxParentDemoCode }]}

</DemoBlock>

### Required group

Set `required` and provide `requiredMessage` when at least one enabled group member must be checked. The group uses native custom validity on an enabled member, so form submission, `checkValidity()`, `reportValidity()`, `novalidate`, and `formnovalidate` retain their browser behaviour.

Wrap the group in [Field](/docs/components/field) to connect descriptions and visible error messages to the group.

Set `disabled` on `CheckboxGroup.Root` to disable its parent and members. A member that was independently disabled remains disabled if the group is enabled later.

`ormo:value-change` fires after a member, parent, or `value` property assignment changes the selected values. It bubbles across shadow boundaries, cannot be cancelled, and exposes the updated `value` and a `reason` of `"member"`, `"parent"`, or `"programmatic"` in `event.detail`. Assigning the current value does not emit an event.

<CodeBlock

group.value = ["http", "https"];
group.disabled = true;`}

## Accessibility

`Checkbox` uses native checkbox semantics, focus, keyboard behaviour, form participation, and mixed-state exposure. Every checkbox needs an accessible name. Prefer a wrapping `<label>` or a sibling `<label for="…">`; use `aria-label` or `aria-labelledby` when visible label text is unavailable.

`CheckboxGroup.Root` follows the [WAI-ARIA Checkbox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/). It uses `role="group"` and an accessible name supplied by `CheckboxGroup.Label`, `aria-label`, or `aria-labelledby`. Each member still needs its own label.

The group does not use arrow-key navigation. Native checkboxes remain separate controls in the document Tab order.

## Styling

Checkbox ships no layout or brand styles. The recommended custom composition uses `appearance: none` on the input and places `CheckboxIndicator` over it. Style the input’s real state with `:checked`, `:indeterminate`, `:disabled`, `:required`, `:valid`, and `:invalid`. Leave its native appearance intact when the operating-system checkbox is preferred.

`CheckboxIndicator` includes only a low-specificity `pointer-events: none` rule so a decorative overlay cannot steal input from the native checkbox. Attributes prefixed with `data-ormo-*` are internal runtime selectors, not styling APIs.

## Runtime

A binary standalone `Checkbox` renders only a native input and ships no client JavaScript. `CheckboxIndicator` adds one behaviour-critical CSS rule but no production JavaScript. Setting `indeterminate` loads a small runtime that applies the initial DOM property once.

`CheckboxGroup.Root` always loads its custom-element runtime for live names, selected values, aggregate and parent state, disabled cascading, validation, form reset, and the browser API. Server rendering already applies member names, default values, accessible label relationships, disabled state, and initial aggregate state. Without JavaScript, individual members retain native focus, activation, submission, and validation; parent selection, live aggregate state, group validation, and the group browser API are unavailable.

## Anatomy

Tooltip content supplements a trigger’s existing accessible name. Keep it short and non-interactive; use Popover for controls or rich content.

<CodeBlock lang="astro" code={`---
import * as Tooltip from "@ormo/primitives/tooltip";
---

<Tooltip.Root>
  <Tooltip.Trigger aria-label="Save document">Save</Tooltip.Trigger>
  <Tooltip.Content>Save</Tooltip.Content>
</Tooltip.Root>`} />

## JavaScript API

The `<ormo-tooltip>` element exposes `delay`, `closeDelay`, `disabled`, readonly `open`, and `show()` and `hide()`. `ormo:tooltip-open-change` bubbles with `{ open, reason }`.

<CodeBlock lang="js" code={`tooltip.addEventListener("ormo:tooltip-open-change", (event) => {
  console.log(event.detail.open, event.detail.reason);
});

tooltip.show();
tooltip.hide();`} />

## Accessibility

Content uses `role="tooltip"` and is referenced from the trigger with `aria-describedby` only while open. It never receives focus and must not contain links, buttons or other interactive content. The trigger must retain a useful accessible name without the tooltip.

## Styling

Style consumer classes and public `data-state`, `data-open`, `data-side`, `data-align`, `data-starting-style` and `data-ending-style` hooks. Content exposes `--ormo-tooltip-side-offset`, `--ormo-tooltip-trigger-width` and `--ormo-tooltip-trigger-height`. Respect reduced motion for transitions.

## Runtime

The server renders the trigger and hidden tooltip content. JavaScript coordinates pointer/focus interest, delays, description relationships, dismissal, events and positioning. The optional floating entry registers Floating UI. Without JavaScript, the tooltip remains unavailable and the trigger retains its native behaviour and accessible name.

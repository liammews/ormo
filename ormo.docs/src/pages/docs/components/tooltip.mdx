## Default

Tooltip shows a brief non-interactive description when the user hovers or focuses a trigger. Focus stays on the trigger. Content is hoverable, dismissible with Escape, and persistent while interest remains — meeting WCAG 1.4.13.

## When to use Tooltip vs Popover

Decide from the **purpose of the trigger**, not from how the popup looks:

- If the trigger’s purpose is **unrelated** to opening the popup — for example a Bold control that also needs a short label — use **Tooltip**.
- If the trigger’s purpose is **to open the popup itself** — for example an info icon whose only job is to show help — use **[Popover](/docs/components/popover)**.

That second case is sometimes called an _infotip_. Prefer Popover for it: Ormo Popover opens on click, so touch users and keyboard / screen-reader users can reach the content deliberately. Tooltip content must stay non-interactive and is easy to miss on touch devices.

Use Popover when the panel needs links, forms, or other focusable controls. Do not put those inside Tooltip Content.

## Anatomy

Compose a trigger button and the tooltip content:

<CodeBlock
  lang="astro"
  code={`---
import * as Tooltip from "@ormo/primitives/tooltip";
---

<Tooltip.Root>
  <Tooltip.Trigger aria-label="Bold">B</Tooltip.Trigger>
  <Tooltip.Content side="top" sideOffset={6}>
    Bold
  </Tooltip.Content>
</Tooltip.Root>`}
/>

Content renders a <code>div</code> with <code>role="tooltip"</code> and the Popover API (<code>popover="hint"</code> when supported, otherwise <code>manual</code>). While open, Ormo connects the trigger through <code>aria-describedby</code>. Default placement uses CSS Anchor Positioning.

Trigger always renders a native <code>&lt;button&gt;</code>. Put icons and labels in its slot — do not nest another button inside Trigger.

## Accessibility

Tooltip follows the APG tooltip pattern: <code>role="tooltip"</code> on Content and <code>aria-describedby</code> on the active Trigger while open. Focus never moves into Content.

WCAG 1.4.13 requirements:

- **Dismissible** — Escape closes without moving pointer or focus.
- **Hoverable** — the pointer can move from Trigger onto Content without it disappearing (<code>closeDelay</code> supports the gap).
- **Persistent** — Content stays until interest ends, Escape, or trigger activation. There is no auto-hide timer while interest remains.

Do not put interactive content in Tooltip. Use [Popover](/docs/components/popover) for that — including info-icon help (_infotips_). See [When to use Tooltip vs Popover](#when-to-use-tooltip-vs-popover). Tooltip does not implement a long-press/touch path in v1; keyboard users reach it through focus.

Development builds and the optional Ormo toolbar report missing or multiple Content parts, focusable descendants in Content, invalid detached Triggers, and floating positioning without the floating import.

## Development toolbar

With the optional [Ormo development toolbar](/docs/dev-toolbar) enabled, Astro’s toolbar scans rendered Tooltips and flags common composition mistakes:

- Detached Triggers with an empty or invalid Root target
- Roots with no Content part or more than one Content part
- Content that contains focusable elements
- <code>positioning="floating"</code> without the floating entry import

## Keyboard behaviour

- Focusing Trigger opens Content immediately.
- <kbd>Escape</kbd> closes Content without moving focus.
- Activating Trigger (click / Enter / Space) closes Content if it was open.
- Tab moves normally; Content is not in the tab order.

## Styling

Pass your own <code>class</code> values to each part. Public state hooks are <code>data-state="open|closed"</code>, <code>data-open</code>, Content <code>data-side</code> / <code>data-align</code> (requested placement), Floating UI <code>data-resolved-side</code> / <code>data-resolved-align</code>, and brief <code>data-starting-style</code> / <code>data-ending-style</code> transition attributes.

CSS custom properties set by Ormo:

- <code>--ormo-tooltip-side-offset</code> — from Content <code>sideOffset</code>
- <code>--ormo-tooltip-anchor</code> — CSS Anchor name when using css-anchor
  positioning
- <code>--ormo-tooltip-trigger-width</code> /
  <code>--ormo-tooltip-trigger-height</code> — measured from the trigger when
  Content opens (cleared on close)

Floating UI may also write <code>left</code> / <code>top</code> on Content. Attributes prefixed with <code>data-ormo-\*</code> are internal runtime selectors.

## Runtime

Tooltip loads one Astro-processed, deduplicated runtime. The browser owns top-layer rendering through the Popover API. Ormo connects parts, manages interest timing and WCAG 1.4.13 behaviour, coordinates exclusive open and the page-level skip-delay grace period, applies CSS Anchor hooks, and handles Astro client-router document swaps.

The Floating UI entry is separate: importing <code>@ormo/primitives/tooltip/floating</code> registers that engine. Pages that never import it never download Floating UI.

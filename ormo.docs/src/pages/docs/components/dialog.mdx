## Default

Dialog opens a native <code>&lt;dialog&gt;</code> as a modal window for a focused task or supporting information. It makes the rest of the page inert, contains keyboard focus, closes with <kbd>Escape</kbd> or a pointer press on the backdrop, and returns focus to the control that opened it.

Use [Alert Dialog](/docs/components/alert-dialog) instead when an urgent message requires an immediate response, especially before an irreversible action.

## Anatomy

Compose the trigger, modal content, accessible name, optional description, and a visible way to close:

<CodeBlock
  lang="astro"
  code={`---
import * as Dialog from "@ormo/primitives/dialog";
---

<Dialog.Root>
  <Dialog.Trigger>Edit profile</Dialog.Trigger>

  <Dialog.Content>
    <Dialog.Title>Edit profile</Dialog.Title>
    <Dialog.Description>
      Change how your name appears to other people.
    </Dialog.Description>

    <!-- Forms, buttons, and application content compose normally. -->
    <Dialog.Close>Close</Dialog.Close>

  </Dialog.Content>
</Dialog.Root>`}
/>

Content always renders <code>&lt;dialog role="dialog" aria-modal="true"&gt;</code>. Ormo generates IDs and connects Title and Description through <code>aria-labelledby</code> and <code>aria-describedby</code>. Trigger opens Content with the native <code>showModal()</code> method.

## Examples

### Detached triggers

Add <code>for</code> with a Root <code>id</code> when a Trigger is rendered elsewhere in the document. Use the ID without a leading <code>#</code>. Multiple descendant and detached Triggers can control the same Root.

Ormo connects every matching Trigger with <code>aria-controls</code>, synchronises its open state, and returns focus to the exact Trigger that opened the dialog.

### Pointer dismissal

Backdrop presses close Dialog by default. Set <code>disablePointerDismissal</code> when an accidental pointer dismissal would discard progress. Keep a visible Close control, and do not disable Escape unless the application is temporarily unable to close safely.

This example omits Description deliberately: its structured list should be read using normal screen-reader navigation instead of being announced as one flattened string.

### Title

Provides the visible accessible name. Its <code>as</code> prop accepts <code>h1</code> through <code>h6</code> and defaults to <code>h2</code>.

### Description

Provides a concise description of the dialog purpose and defaults to <code>p</code>. It may render as <code>div</code>. Omit this part for long or structured content that users should navigate semantically.

### Close

Renders an Ormo [Button](/docs/components/button) that closes Content. It accepts Button's native-button props, including <code>value</code>, <code>disabled</code>, <code>focusableWhenDisabled</code>, and <code>pending</code>. Its value becomes the native dialog <code>returnValue</code>.

The <code>ormo-dialog</code> element exposes framework-independent modal control:

      description:
        "Opens Content modally and remembers the focused element for restoration.",
    },

      description: "Closes Content and optionally sets its returnValue.",
    },
  ]}

Listen for <code>ormo:dialog-open-change</code> on Root. It bubbles with <code>open</code>, <code>reason</code>, and <code>returnValue</code>. Reason is <code>trigger</code>, <code>close</code>, <code>escape</code>, <code>outside</code>, or <code>programmatic</code>.

There is no Astro <code>open</code> or <code>defaultOpen</code> prop. Open Dialog with Trigger or <code>showModal()</code> after the custom element connects — native modal opening requires JavaScript.

A Close click occurs before Ormo handles it, so a synchronous <code>event.preventDefault()</code> keeps the dialog open. Prevent the native, cancellable <code>cancel</code> event on Content to override Escape dismissal. A native <code>&lt;form method="dialog"&gt;</code> submit also closes Content; Ormo reports that close as <code>programmatic</code>.

## Accessibility

Dialog follows the [WAI-ARIA modal Dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/). Every Dialog needs a concise accessible name. Prefer a visible Title; use <code>aria-label</code> or <code>aria-labelledby</code> only when another visible element supplies the name.

The first tabbable element receives focus by default. Add native <code>autofocus</code> to choose a more appropriate target. For large or structured content, place <code>autofocus tabindex="-1"</code> on Title or another static element near the start and omit Description so screen-reader users can navigate the structure.

Always include a visible Close control. Escape and backdrop dismissal alone are not sufficient for touch screen-reader and pointer users. Native modal behaviour makes outside content inert; consumer styling must also make the modal boundary visually apparent.

Development builds and the optional Ormo toolbar report missing or multiple Content parts, missing accessible names, missing Close controls, invalid final-focus selectors, and detached Triggers with invalid targets.

## Development toolbar

With the optional [Ormo development toolbar](/docs/dev-toolbar) enabled, Astro’s toolbar scans rendered Dialogs and flags common composition mistakes:

- Detached Triggers with an empty or invalid Root target
- Roots with no Content part or more than one Content part
- Content without a Title or another accessible name
- Content without a visible Close control
- Invalid <code>finalFocus</code> CSS selectors, or selectors that do not match an available programmatically focusable element

Select an issue in the toolbar to jump to the element. These checks catch structural mistakes during development; they do not replace keyboard and screen-reader testing.

## Keyboard behaviour

- <kbd>Tab</kbd> and <kbd>Shift</kbd> + <kbd>Tab</kbd> move through the controls
  inside Content and wrap at either end.
- <kbd>Escape</kbd> closes Content unless its native <code>cancel</code> event
  is prevented.
- Activating Close closes Content after consumer click handlers run.

## Styling

Pass your own <code>class</code> values to each part. Public part state hooks are <code>data-state="open|closed"</code>, <code>data-open</code>, and Content's brief <code>data-starting-style</code> / <code>data-ending-style</code> transition attributes. Attributes prefixed with <code>data-ormo-\*</code> on primitive parts are internal runtime selectors, not styling APIs.

While any Ormo modal is open, the document element exposes <code>data-ormo-scroll-locked</code>. That attribute is shared document-level state for Dialog and [Alert Dialog](/docs/components/alert-dialog) — use it to observe or style around background scroll locking. It remains until the final nested or sibling modal closes.

Style the modal surface through your Content class and the inert-page overlay through that class's <code>::backdrop</code>. Native discrete transitions can keep a closing dialog in the top layer without delaying its semantic closed state:

<CodeBlock
  lang="css"
  code={`.dialog {
  transition:
    opacity 120ms,
    overlay 120ms allow-discrete,
    display 120ms allow-discrete;
}

.dialog[data-starting-style],
.dialog[data-ending-style] {
opacity: 0;
}

.dialog::backdrop {
background: rgb(0 0 0 / 55%);
}

@media (prefers-reduced-motion: reduce) {
.dialog { transition: none; }
}`}
/>

Ormo applies no component CSS. Consumers own surface and backdrop distinction, contrast, focus indicators, viewport-safe sizing, and reduced-motion behaviour.

## Runtime

Dialog loads one Astro-processed, deduplicated runtime. The browser owns the modal top layer and outside-page inertness. Ormo connects its parts, locks background document scrolling, manages initial and final focus, supplies a cross-browser Tab sequence, coordinates dismissal and state, and handles Astro client-router document swaps.

One document-scoped listener and observer coordinate descendant, detached, and dynamically inserted Triggers regardless of how many Dialogs are rendered. Scroll locking is shared with [Alert Dialog](/docs/components/alert-dialog) and remains active until the final nested or sibling modal closes. An authored inline <code>overflow</code> value is restored afterward.

Before an Astro client-router document swap, an open dialog closes synchronously and restores focus. This lets Astro's own focus-preservation step begin from a meaningful element rather than from content that is about to be removed.

## Usage

Use a dialog for a focused task or supporting content that temporarily makes the rest of the page unavailable. Use [Alert Dialog](/docs/components/alert-dialog) when an important or destructive decision requires an explicit response, and [Popover](/docs/components/popover) when the rest of the page should remain interactive.

The component always opens modally. It uses the native `<dialog>` top layer rather than rendering a portal or a separate overlay element.

## Anatomy

Import the component and assemble its parts. Include a visible title and at least one visible close control.

<CodeBlock
  lang="astro"
  code={`---
import * as Dialog from "@ormo/primitives/dialog";
---

<Dialog.Root>
  <Dialog.Trigger>Edit profile</Dialog.Trigger>

  <Dialog.Content>
    <Dialog.Title>Edit profile</Dialog.Title>
    <Dialog.Description>
      Change how your name appears to other people.
    </Dialog.Description>

    <label for="display-name">Display name</label>
    <input id="display-name" name="displayName" />

    <Dialog.Close>Cancel</Dialog.Close>
    <Dialog.Close value="save">Save changes</Dialog.Close>

  </Dialog.Content>
</Dialog.Root>`}
/>

## Examples

### Initial focus

When the dialog opens, focus moves to the first eligible descendant with `autofocus`, then the first tabbable element, and finally `Dialog.Content`. Add `tabindex="-1"` and `autofocus` to `Dialog.Title` when users should read structured or potentially overflowing content before reaching the controls.

Only one element within `Dialog.Content` should have `autofocus`.

<CodeBlock
  lang="astro"
  code={`<Dialog.Content>
  <Dialog.Title tabindex="-1" autofocus>
    Terms of service
  </Dialog.Title>
  <!-- Structured content and controls -->
</Dialog.Content>`}
/>

### Prevent pointer dismissal

Set `disablePointerDismissal` when an outside pointer press should not close the dialog. <kbd>Escape</kbd> and `Dialog.Close` continue to work.

### Prevent dismissal

Listen for `ormo:dialog-before-close` and call `event.preventDefault()` to keep the dialog open after `Dialog.Close`, an outside pointer press, or <kbd>Escape</kbd>. Use this for unsaved-change confirmation or another condition that must be resolved before dismissal.

<CodeBlock
  lang="js"
  code={`const dialog = document.querySelector("ormo-dialog");

dialog?.addEventListener("ormo:dialog-before-close", (event) => {
if (hasUnsavedChanges()) {
event.preventDefault();
showDiscardConfirmation();
}
});`}
/>

The event represents a user dismissal request. Calling `close()` programmatically and submitting a native `<form method="dialog">` do not fire it.

### Native dialog form

A `Dialog.Close` with `type="submit"` defers to its form rather than closing immediately. Use `<form method="dialog">` for synchronous native validation and return-value behaviour. For asynchronous submission, prevent the form submission, await the operation, then call `close()`.

<CodeBlock
  lang="astro"
  code={`<Dialog.Content>
  <Dialog.Title>Rename project</Dialog.Title>

  <form method="dialog">
    <label for="project-name">Project name</label>
    <input id="project-name" name="projectName" required />

    <Dialog.Close type="button">Cancel</Dialog.Close>
    <Dialog.Close type="submit" value="saved">
      Save
    </Dialog.Close>

  </form>
</Dialog.Content>`}
/>

## JavaScript API

`Dialog.Root` renders an `<ormo-dialog>` custom element for framework-independent client-side control.

    },
    {
      name: "close(returnValue?)",
      type: "(returnValue?: string) => void",
      description:
        "Closes the content element programmatically and optionally sets its native returnValue. Programmatic closing cannot be cancelled.",
    },

`ormo:dialog-before-close` fires before a user-requested dismissal from `Dialog.Close`, an outside pointer press, or <kbd>Escape</kbd>. It bubbles across shadow boundaries and can be cancelled. Its `detail` contains `reason`, `returnValue`, and `originalEvent`.

The reason is `close`, `outside`, or `escape`. `returnValue` contains the activated close control’s value and is otherwise empty. Calling `event.preventDefault()` leaves the dialog open.

`ormo:dialog-open-change` fires after the dialog opens or closes. It bubbles across shadow boundaries, cannot be cancelled, and includes `open`, `reason`, and `returnValue` in `event.detail`.

The opening reason is `trigger` or `programmatic`. The closing reason is `close`, `escape`, `outside`, or `programmatic`.

<CodeBlock
  lang="js"
  code={`const dialog = document.querySelector("ormo-dialog");

dialog?.addEventListener("ormo:dialog-before-close", (event) => {
console.log(event.detail.reason);
});

dialog?.addEventListener("ormo:dialog-open-change", (event) => {
console.log(event.detail.open);
console.log(event.detail.reason);
console.log(event.detail.returnValue);
});

dialog?.showModal();
dialog?.close("complete");`}
/>

## Accessibility

The component follows the [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) on a native modal `<dialog>`. `Dialog.Title` supplies the accessible name, and a concise `Dialog.Description` supplies the optional accessible description.

Include a visible `Dialog.Close` so keyboard and touch screen-reader users always have an explicit way to leave the dialog. Development diagnostics warn when `Dialog.Content` has no accessible name or visible close control.

On open, focus moves to the first eligible element with `autofocus`, then the first tabbable element, and finally `Dialog.Content`. Focus remains inside while open. On close, focus returns to an explicit `finalFocus` target or the element that opened the dialog.

## Runtime

`Dialog.Root` loads one deduplicated runtime that opens `Dialog.Content` with the native modal API, generates and reconciles ARIA relationships, manages focus and scroll locking, coordinates triggers and transitions, and handles Astro navigation and DOM lifecycle changes. The server renders a closed `<dialog>` with its semantic parts; without JavaScript, the dialog remains closed and its trigger cannot open it.

## Default

Avatar shows a profile image when it loads, and falls back to initials or other content when the image is missing or fails. It is presentational by itself: wrap it in a Button or link when the avatar should be interactive.

<DemoBlock code={avatarDemoCode}>
  <AvatarDemo />
</DemoBlock>

## Anatomy

Compose a Root with an optional Image and a Fallback. Place Image before Fallback so server HTML can hide the fallback optimistically when a source is present.

<CodeBlock
  lang="astro"
  code={`---
import * as Avatar from "@ormo/primitives/avatar";
---

<Avatar.Root>
  <Avatar.Image src="..." alt="Ada Lovelace" width="40" height="40" />
  <Avatar.Fallback>AL</Avatar.Fallback>
</Avatar.Root>`}
/>

## Examples

### Fallback only

Omit Image when you only have initials or another stand-in. Give Root an accessible name when the avatar is the sole identity cue.

<DemoBlock code={avatarFallbackOnlyDemoCode}>
  <AvatarFallbackOnlyDemo />
</DemoBlock>

### Broken or missing image

When the image fails to load, Avatar hides the image and shows Fallback. Name Root when Fallback may become the only visible face so assistive technology still hears the person’s name rather than bare initials.

  <AvatarBrokenDemo />
</DemoBlock>

### Delayed fallback

Set <code>delay</code> on Fallback to wait before showing it while the image is still loading. This reduces flash when the image arrives quickly from cache.

  <AvatarDelayedFallbackDemo />
</DemoBlock>

### Decorative beside a visible name

When adjacent text already names the person, mark the image decorative with <code>alt=""</code> so assistive technology does not announce the name twice.

<DemoBlock code={avatarDecorativeDemoCode}>
  <AvatarDecorativeDemo />
</DemoBlock>

### Icon fallback

Fallback can contain a consumer-owned icon. Hide decorative icons from assistive technology and keep the accessible name on Root or adjacent text.

<DemoBlock code={avatarIconFallbackDemoCode}>
  <AvatarIconFallbackDemo />
</DemoBlock>

### Interactive button or link

Avatar itself is not focusable. Wrap it in Button or a link when it should open a profile or trigger an action. Put the accessible name on the wrapper, hide the Avatar from the accessibility tree with <code>aria-hidden="true"</code>, and use <code>alt=""</code> on Image.

## Browser API and events

Root exposes loading status for scripts and islands.

| Member                                         | Type                                                 | Description                                                                    |
| ---------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| <code>imageLoadingStatus</code>                | <code>"loading" \| "loaded" \| "error"</code>        | Current image loading status.                                                  |
| <code>ormo:avatar-loading-status-change</code> | <code>CustomEvent&lt;&#123; status &#125;&gt;</code> | Fired when <code>imageLoadingStatus</code> changes after the first connection. |

## Accessibility

Avatar does not invent names or roles. Authors choose the correct WCAG 1.1.1 treatment for the context:

1. **Decorative** — When a visible name sits beside the avatar, use <code>alt=""</code> on Image. Do not add a second name on Root. Optionally set <code>aria-hidden="true"</code> on Root when the whole graphic is redundant.
2. **Informative image** — Provide a meaningful <code>alt</code> on Image (typically the person’s or entity’s name).
3. **Fallback only** — Put an accessible name on Root, usually <code>role="img"</code> and <code>aria-label</code> with the full name. Initials alone are often announced letter by letter without <code>role="img"</code>.
4. **Image error or loading fallback** — When Image is hidden and Fallback is showing, the image <code>alt</code> is no longer exposed. Name Root (or keep adjacent visible text) so the identity is still available.
5. **Icons in Fallback** — Mark decorative SVGs with <code>aria-hidden="true"</code>.
6. **Interactive** — Wrap Avatar in Button or a link. The wrapper owns focus and the accessible name; hide Avatar with <code>aria-hidden="true"</code> and use <code>alt=""</code>.

In development, Ormo warns when Image is missing the <code>alt</code> attribute entirely. An empty <code>alt=""</code> is valid and does not warn.

## Keyboard behaviour

Avatar is not focusable and has no keyboard behaviour of its own. Interactive wrappers supply their normal keyboard support.

## Styling

| Attribute                | Element          | Description                                                       |
| ------------------------ | ---------------- | ----------------------------------------------------------------- |
| <code>data-status</code> | Root             | <code>loading</code>, <code>loaded</code>, or <code>error</code>. |
| <code>hidden</code>      | Image / Fallback | Applied to the inactive face.                                     |
| <code>data-delay</code>  | Fallback         | Present when a positive <code>delay</code> is set.                |

Avatar ships no layout or brand styles. Size, shape, colour, and typography belong to the consumer.

When styling Fallback with <code>display</code> (for example <code>display: flex</code>), scope it to <code>:not([hidden])</code> or add an explicit <code>[hidden] &#123; display: none; &#125;</code> rule so the inactive face stays out of layout. Stacking Image and Fallback with absolute positioning inside Root also prevents them from sitting side by side if both are briefly visible.

## Runtime

Root loads a small runtime that tracks image <code>load</code> and <code>error</code>, coordinates Fallback visibility (including <code>delay</code>), and keeps <code>data-status</code> in sync. Without JavaScript, a Fallback that was hidden for an Image with a source stays hidden; a broken image then follows native browser behaviour until the runtime connects.

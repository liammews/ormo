## Usage

Use an avatar to represent a person, account, or identity when a portrait may need to transition to initials or an icon while loading or after an error. Use a native `<img>` without the avatar component when loading coordination and fallback content are unnecessary.

Choose one accessible-naming strategy and keep it consistent across every loading state:

- When fallback initials or an icon replace the portrait, add `role="img"` and `aria-label` to `Avatar.Root`, then use `alt=""` on `Avatar.Image`. The root exposes one stable name while the visible content changes.
- When `Avatar.Image` supplies meaningful `alt`, ensure `Avatar.Fallback` exposes an equivalent identity rather than ambiguous initials alone.
- When adjacent text or a parent control already supplies the identity, add `aria-hidden="true"` to `Avatar.Root` and use `alt=""` on `Avatar.Image`.

## Anatomy

Import the component and assemble its image and fallback. This example gives the root a stable accessible name because initials replace the portrait while it loads or after an error.

<CodeBlock
  lang="astro"
  code={`---
import * as Avatar from "@ormo/primitives/avatar";
---

<Avatar.Root role="img" aria-label="Person name">
  <Avatar.Image
    src="/avatars/person-name.jpg"
    alt=""
    width="40"
    height="40"
  />
  <Avatar.Fallback>PN</Avatar.Fallback>
</Avatar.Root>`}
/>

## JavaScript API

`Avatar.Root` renders an `<ormo-avatar>` custom element that exposes its current image state for framework-independent integrations.

`ormo:avatar-loading-status-change` fires when the status changes after the custom element has initialised. It bubbles, does not cross shadow boundaries, cannot be cancelled, and provides `{ status }` in `event.detail`. The initial status does not emit an event; read `imageLoadingStatus` when initial state is required.

## Accessibility

`Avatar.Image` uses native `<img>` semantics and requires `alt`. When the root owns the accessible identity, add `role="img"` and `aria-label` to `Avatar.Root` and use `alt=""` so the image and fallback do not create duplicate names. This keeps the same identity available while the visible part changes.

Alternatively, give `Avatar.Image` meaningful `alt` when the native image should expose the identity. In that model, `Avatar.Fallback` must communicate the same person or account when the image is unavailable; initials alone are only sufficient when they identify the person unambiguously in context.

When adjacent text identifies the person or a parent control has an accessible name, add `aria-hidden="true"` to `Avatar.Root` and use `alt=""` on `Avatar.Image`. For a fallback-only or icon avatar that represents a person, use the root-owned naming strategy and add `aria-hidden="true"` to any decorative fallback SVG.

`Avatar.Root` does not participate in keyboard navigation. If the avatar triggers an action or navigation, place `Avatar.Root` inside a native button or link and add `aria-label` and focus styling to that control.

## Runtime

`Avatar.Root` loads one deduplicated runtime that observes image sources, loading results, fallback delays, and inserted or removed parts. Initial loading or error state is rendered on the server. Without JavaScript, an immediate server-rendered fallback remains visible, but the image cannot transition to loaded and a delayed fallback remains hidden.

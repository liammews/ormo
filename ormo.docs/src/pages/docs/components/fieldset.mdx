## Anatomy

Import both parts and make `Fieldset.Legend` the first child of `Fieldset.Root`. The native legend supplies the accessible name for the group. Every control inside the group still needs its own label.

<CodeBlock
  lang="astro"
  code={`---
import * as Fieldset from "@ormo/primitives/fieldset";
---

<Fieldset.Root aria-describedby="delivery-hint">
  <Fieldset.Legend>Delivery address</Fieldset.Legend>
  <p id="delivery-hint">
    Enter the address where this order should be sent.
  </p>

<label for="address-line">Address line</label>
<input
  id="address-line"
  name="address-line"
  autocomplete="shipping address-line1"
/>

  <label for="town">Town or city</label>
  <input
    id="town"
    name="town"
    autocomplete="shipping address-level2"
  />
</Fieldset.Root>`}
/>

Use [Field](/docs/components/field) for one control with its own label, description, error, and validation state. Use the fieldset when one caption applies to several related controls. Choose [CheckboxGroup](/docs/components/checkbox#checkbox-group) or [RadioGroup](/docs/components/radio#radio-group) when the controls need coordinated values, required-group validation, or a browser API.

Set `disabled` on `Fieldset.Root` to disable every descendant form control. The legend continues to name the group while its controls are unavailable.

### Form association

The native `form` attribute associates a fieldset with a form elsewhere in the document, but it does not associate the fieldset’s descendant controls. Add the same `form` id to each out-of-form control that should participate in submission.

The fieldset’s `name` is available through the form and DOM APIs; it does not add a value to `FormData`.

### Related choices

A fieldset is the zero-JavaScript option when checkboxes or radios need only a shared caption. Keep a native name on each member and label every individual option:

<CodeBlock
  lang="astro"
  code={`---
import * as Fieldset from "@ormo/primitives/fieldset";
import { Radio } from "@ormo/primitives/radio";
---

<Fieldset.Root>
  <Fieldset.Legend>Billing cycle</Fieldset.Legend>
  <label>
    <Radio name="billing-cycle" value="monthly" checked />
    Monthly
  </label>
  <label>
    <Radio name="billing-cycle" value="yearly" />
    Yearly
  </label>
</Fieldset.Root>`}
/>

## Accessibility

The native fieldset and legend relationship provides the group role and accessible name without ARIA. Keep `Fieldset.Legend` visible, non-empty, and first in `Fieldset.Root`. Every descendant input, select, textarea, checkbox, or radio still needs its own accessible label.

Use `aria-describedby` on `Fieldset.Root` for group-level instructions and errors. Error text should identify the problem and how to correct it, and must not rely on colour alone.

A fieldset does not introduce keyboard interaction. Focus moves through its enabled descendant controls in document order. When the group is disabled, controls in the first legend remain operable while the remaining descendants leave the focus order.

## Styling

Fieldset ships no layout or brand styles. Add `class` to either part and use the native `:disabled` or `:enabled` pseudo-classes for group state. The `data-ormo-fieldset-*` attributes identify internal component structure and are not state APIs.

Native fieldsets have special box-model behaviour and a default `min-inline-size` based on their contents. Set `min-inline-size: 0` when the group must shrink inside a grid or flex layout. A native legend is positioned over the fieldset’s block-start border and shrink-wraps its content.

## Runtime

`Fieldset.Root` and `Fieldset.Legend` render only native HTML and ship no client JavaScript. Group naming, form association, disabled cascading, focus behaviour, and the DOM API work during server rendering and without JavaScript. Any script that changes `disabled` or handles submission is application code rather than Fieldset runtime.

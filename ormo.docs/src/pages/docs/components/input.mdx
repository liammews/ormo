## Anatomy

Import `Input` and provide the same native attributes you would use on an HTML input. Associate it with a visible label directly or compose it with `Field`.

<CodeBlock
  lang="astro"
  code={`---
import { Input } from "@ormo/primitives/input";
---

<label for="email">Email address</label>
<Input id="email" name="email" type="email" autocomplete="email" />`}
/>

## API reference

`Input` renders an `<input>` and forwards its native attributes. It does not wrap the element or replace native value, form, validation or event APIs.

## Accessibility

`Input` preserves native input semantics. Authors must provide an accessible name through a `<label>`, `aria-label` or `aria-labelledby`, choose an appropriate `type` and `autocomplete` value, and expose validation errors in text. Keyboard and assistive-technology behaviour remains the browser’s native behaviour for the selected type.

## Styling

The primitive ships no presentation CSS. Style the passed `class`, native pseudo-classes such as `:focus-visible`, `:disabled` and `:user-invalid`, and Field’s public state hooks when composed. `data-ormo-input` is an internal ownership selector rather than a styling contract.

## Runtime

`Input` ships no JavaScript. The server renders one native `<input>`, so values, validation, events, forms and keyboard behaviour work identically without client-side JavaScript.

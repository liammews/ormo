## Events

Listen for <code>ormo:value-change</code> on the root before the value changes. The event bubbles and crosses shadow boundaries. User-initiated changes can be cancelled with <code>preventDefault()</code>. Automatic fallbacks (for example, when the selected tab is removed or disabled) are not cancellable.

<CodeBlock
  lang="js"
  code={`tabs.addEventListener("ormo:value-change", (event) => {
  console.log(event.detail.value);
});`}
/>

## Controlling value after render

Astro props configure the initial tab. After the page loads, read and write selection on the <code>ormo-tabs</code> element. Assigning <code>value</code> updates the tabs immediately. Listening for <code>ormo:value-change</code> and calling <code>preventDefault()</code> keeps the previous value, which is the controlled pattern for plain Astro scripts and islands.

<CodeBlock
  lang="astro"
  code={`---
import * as Tabs from "@ormo/primitives/tabs";
---

<Tabs.Root id="account" defaultValue="overview">
  <Tabs.List aria-label="Account">
    <Tabs.Tab value="overview">Overview</Tabs.Tab>
    <Tabs.Tab value="projects">Projects</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel value="overview">Overview content</Tabs.Panel>
  <Tabs.Panel value="projects">Projects content</Tabs.Panel>
</Tabs.Root>

<script>
  const tabs = document.getElementById("account");

  tabs?.addEventListener("ormo:value-change", (event) => {
    // Keep the previous value to fully control selection.
    // event.preventDefault();
    console.log(event.detail.value);
  });

  // Select a tab from application code:
  // tabs.value = "projects";
</script>`}

/>

## Accessibility

Tabs follow the WAI-ARIA Authoring Practices tabs pattern:

- List uses <code>role="tablist"</code> and must have an accessible name.
- Each Tab uses <code>role="tab"</code> with <code>aria-selected</code> and <code>aria-controls</code>.
- Each Panel uses <code>role="tabpanel"</code> with <code>aria-labelledby</code> pointing at its tab.
- Only one tab is selected at a time. Inactive panels stay in the DOM with the <code>hidden</code> attribute.
- The active panel is focusable (<code>tabindex="0"</code>) so assistive technology users can move from the tablist into panel content.

Prefer Tabs for in-page panel switching. For navigation between URLs, use links in a navigation landmark instead.

In development, Ormo warns when the tablist is unnamed, when Tab and Panel values do not match, or when a Tab is outside List.

## Development toolbar

With the optional [Ormo development toolbar](/docs/dev-toolbar) enabled, Astro’s toolbar scans rendered Tabs and flags common composition mistakes:

- Roots without a List
- Lists without an accessible name
- Tab or Panel parts with missing or duplicate values
- Tabs outside a List
- Tabs without an accessible name
- Tab values without a matching Panel, and Panel values without a matching Tab

Select an issue in the toolbar to jump to the element. These checks catch structural mistakes during development; they do not replace keyboard and screen-reader testing.

## Runtime

Root loads a small runtime that manages selection, ARIA relationships, roving tabindex, and keyboard behaviour. Without JavaScript, the initially selected panel stays visible and other panels stay hidden; tabs do not switch until the runtime connects.

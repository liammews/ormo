## Anatomy

Put one `PasswordField.Input` and one `PasswordField.Toggle` inside `PasswordField.Root`. Put the input before the toggle so focus follows a useful order. The toggle labels are required and can be translated by the application.

<CodeBlock
  lang="astro"
  code={`---
import * as Field from "@ormo/primitives/field";
import * as PasswordField from "@ormo/primitives/password-field";
---

<form method="post">
  <Field.Root>
    <Field.Label>Password</Field.Label>
    <PasswordField.Root>
      <PasswordField.Input
        name="password"
        autocomplete="current-password"
        required
      />
      <PasswordField.Toggle
        showLabel="Show password"
        hideLabel="Hide password"
      >
        Visibility
      </PasswordField.Toggle>
    </PasswordField.Root>
  </Field.Root>
</form>`}
/>

Use `autocomplete="current-password"` for sign-in and reauthentication. Use `autocomplete="new-password"` when a person creates or changes a password. Keep paste and password-manager filling available.

## Examples

### New password

Native password constraints continue to work. Describe requirements before entry and report each validation problem in text. Do not prevent paste or impose rules that reject long passphrases without a security requirement.

### Initially visible

Set `defaultVisible` only when clear-text initial output is a deliberate product requirement. The server then renders `type="text"`, which can expose an authored value in page source, screenshots, recordings, or nearby viewing.

## JavaScript API

The `<ormo-password-field>` custom element exposes visibility without exposing the password value.

<PropsTable
  id="password-field-browser-api"
  caption="Password Field browser element API"
  nameHeader="Member"
  rows={[
    {
      name: "visible",
      type: "boolean",
      description: "Gets or sets whether the input displays clear text.",
    },
  ]}
/>

`ormo:password-visibility-change` bubbles and crosses shadow boundaries. It is not cancelable. Its detail contains `visible`, `previousVisible`, and a `reason` of `"toggle"`, `"programmatic"`, `"reset"`, `"submit"`, or `"pagehide"`. It never contains the password value.

<CodeBlock
  lang="js"
  code={`const passwordField = document.querySelector("ormo-password-field");

passwordField.addEventListener("ormo:password-visibility-change", (event) => {
console.log(event.detail.visible, event.detail.reason);
});

passwordField.visible = false;`}
/>

## Accessibility

`PasswordField.Input` keeps native password-input semantics. Give it an accessible name through `Field.Label`, a native `<label>`, `aria-label`, or `aria-labelledby`. Give instructions and errors in text, and associate them with the input.

Pointer activation returns focus to the input. Keyboard and virtual activation keep focus on `PasswordField.Toggle`. The native button responds to <kbd>Enter</kbd> and <kbd>Space</kbd>. The toggle exposes its current state through `aria-pressed` and changes its accessible name for the next action.

Showing a password can help people verify difficult input, but it can also expose the value to nearby people, screen sharing, screenshots, and recordings. The component masks the input after submission, reset, page hiding, or disconnection.

## Security

Password masking is visual only. Scripts on the page can still read the native input value. Use HTTPS for the complete session, prevent script injection, restrict third-party scripts, and hash passwords securely on the server.

Never render a real password through the `value` attribute, put it in logs or analytics, or copy it to client storage. Submit password forms with `method="post"`; GET submission can put credentials in URLs, history, server logs, and analytics. The development runtime warns about these unsafe cases.

Do not block paste, copy, autofill, or password managers. These features reduce transcription and help people use unique credentials.

## Styling

The password field ships no layout or brand styles. Add `class` to each part. Use `data-state`, `data-visible`, `data-hidden`, and `data-disabled` as public styling hooks. Attributes prefixed with `data-ormo-*` identify internal structure and are not styling APIs.

## Runtime

The server renders a native password input, a button, initial visibility state, and Field relationships. A small custom-element runtime changes the existing input type, coordinates focus and state, and masks the password during security-sensitive lifecycle events. Without JavaScript, the input remains masked and usable, and behaviour CSS hides the inactive toggle.

## Usage

Use an alert dialog when a decision interrupts the user’s workflow and requires an explicit response, particularly before an irreversible or destructive action. Use [Dialog](/docs/components/dialog) for a general modal task or supporting content that does not require an urgent decision.

## Anatomy

Import the component and assemble its parts. Include a title, a concise description of the consequences, and at least one action that closes the alert dialog.

<CodeBlock
  lang="astro"
  code={`---
import * as AlertDialog from "@ormo/primitives/alert-dialog";
---

<AlertDialog.Root>
  <AlertDialog.Trigger>Trigger label</AlertDialog.Trigger>

  <AlertDialog.Content>
    <AlertDialog.Title>Dialog title</AlertDialog.Title>
    <AlertDialog.Description>
      Dialog description
    </AlertDialog.Description>

    <AlertDialog.Cancel>Cancel</AlertDialog.Cancel>
    <AlertDialog.Action value="action">
      Action label
    </AlertDialog.Action>

  </AlertDialog.Content>
</AlertDialog.Root>`}
/>

### Pending action

Calling `event.preventDefault()` from an `AlertDialog.Action` click handler keeps the alert dialog open. This allows an asynchronous operation to finish before calling `close()` on the root. Pending state alone does not prevent the action from closing the alert dialog.

Keep the action focusable while pending when its state or accessible description explains why interaction is temporarily unavailable. Announce the result outside the closed alert dialog with a persistent live region.

## JavaScript API

`AlertDialog.Root` renders an `<ormo-alert-dialog>` custom element for framework-independent client-side control.

`ormo:alert-dialog-open-change` fires after the alert dialog opens or closes. It bubbles across shadow boundaries, cannot be cancelled, and includes `open`, `reason`, and `returnValue` in `event.detail`.

The opening reason is `trigger` or `programmatic`. The closing reason is `action`, `cancel`, `escape`, or `programmatic`. `returnValue` is empty when the alert dialog opens and otherwise reflects the value passed by the close control or `close()` method.

<CodeBlock
  lang="js"
  code={`const alertDialog = document.querySelector("ormo-alert-dialog");

alertDialog?.addEventListener("ormo:alert-dialog-open-change", (event) => {
console.log(event.detail.open);
console.log(event.detail.reason);
console.log(event.detail.returnValue);
});

alertDialog?.showModal();
alertDialog?.close("complete");`}
/>

## Accessibility

The component follows the [WAI-ARIA Alert Dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/) on a native modal `<dialog>`. `AlertDialog.Title` supplies the accessible name and `AlertDialog.Description` supplies the accessible description. Include both unless equivalent authored ARIA relationships provide the same information.

Keep the description concise enough to be understood when the alert dialog opens. State the consequence of each choice and use specific action labels such as “Delete project” rather than “Yes”. Include `AlertDialog.Cancel` for destructive decisions unless cancelling is genuinely unavailable.

On open, focus moves to the first eligible element with `autofocus`, then `AlertDialog.Cancel`, then the first tabbable element, and finally `AlertDialog.Content`. Focus remains inside while open. On close, focus returns to an explicit `finalFocus` target or the trigger that opened the alert dialog.

## Runtime

`AlertDialog.Root` loads one deduplicated runtime that opens Content with the native modal API, generates ARIA relationships, manages focus and scroll locking, coordinates triggers and transitions, and handles Astro navigation. The server renders a closed `<dialog>` with its semantic parts; without JavaScript, the alert dialog remains closed and its trigger cannot open it.

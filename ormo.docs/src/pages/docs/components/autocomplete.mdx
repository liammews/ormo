## Anatomy

Autocomplete accepts freeform text and offers optional suggestions. Unlike
Combobox, its current input text is always the submitted value and does not
need to match an item.

<CodeBlock
  lang="astro"
  code={`<Autocomplete.Root name="location">
  <Autocomplete.Input placeholder="Search locations" />
  <Autocomplete.Clear aria-label="Clear location">×</Autocomplete.Clear>
  <Autocomplete.Content>
    <Autocomplete.Item value="London" identifier="london">London</Autocomplete.Item>
    <Autocomplete.Loading>Loading…</Autocomplete.Loading>
    <Autocomplete.Empty>No suggestions found.</Autocomplete.Empty>
  </Autocomplete.Content>
</Autocomplete.Root>`}
/>

## Examples

### Async suggestions

Use `filter="none"` when application code owns results. The primitive owns
interaction and presentation state, not requests, debouncing, caching, or
cancellation.

`Item` accepts `value`, optional `identifier`, `textValue`, `keywords`, and
`disabled`. Value is inserted and submitted. Identifier is event metadata only.
`Clear` is shown only while text exists. `Loading` replaces Empty while the
root is loading.

## Browser API and events

The root exposes `value`, `disabled`, `readOnly`, `loading`, read-only `open`,
and `show()`, `hide()`, and `toggle(force?)`.

Value changes use `ormo:autocomplete-before-value-change` and
`ormo:autocomplete-value-change`. Suggestion selection additionally emits
`ormo:autocomplete-select`; popup changes emit
`ormo:autocomplete-open-change`. Reasons are `input`, `item`, `clear`, and
`programmatic`.

For Floating UI, load the adapter from a client script:

<CodeBlock lang="astro" code={`<Autocomplete.Root positioning="floating">…</Autocomplete.Root>

<script>
  import "@ormo/primitives/autocomplete/floating";
</script>`} />

## Accessibility and keyboard

Focus remains on Input while `aria-activedescendant` identifies a highlighted
suggestion. Arrow keys navigate, Enter accepts a highlighted suggestion,
Escape and Tab dismiss without reverting text, and normal text-editing keys
retain native behavior. IME input is processed after composition commits.
Loading is announced politely and Content exposes `aria-busy`.

## Runtime

Without JavaScript the native text input remains visible, valid, and
submittable. Suggestion content and custom actions stay hidden until the custom
element enhances them.

## Anatomy

Autocomplete accepts freeform text and offers optional suggestions. Unlike
Combobox, its current input text is always the submitted value and does not
need to match an item.

<CodeBlock
  lang="astro"
  code={`<Autocomplete.Root name="location">
  <Autocomplete.Input placeholder="Search locations" />
  <Autocomplete.Clear aria-label="Clear location">×</Autocomplete.Clear>
  <Autocomplete.Content>
    <Autocomplete.Item value="London" identifier="london">London</Autocomplete.Item>
    <Autocomplete.Loading>Loading…</Autocomplete.Loading>
    <Autocomplete.Empty>No suggestions found.</Autocomplete.Empty>
  </Autocomplete.Content>
</Autocomplete.Root>`}
/>

## Examples

### Choose autocomplete or combobox

Use autocomplete when all text is valid and suggestions only help the user.
Use [Combobox](/docs/components/combobox/) when the value must identify one
item in a known collection.

### Async suggestions

Use `filter="none"` when application code owns results. The primitive owns
interaction and presentation state, not requests, debouncing, caching, or
cancellation.

<DemoBlock files={[{ filename: "AutocompleteAsync.astro", code: asyncCode }]}>
  <AutocompleteAsyncDemo />
</DemoBlock>

### Forms and freeform values

`Input` is the real native form control, so required validation, autofill,
submission, and reset continue to work without mirrored state.

<DemoBlock files={[{ filename: "AutocompleteForm.astro", code: formCode }]}>
  <AutocompleteFormDemo />
</DemoBlock>

### Filtering, aliases, and disabled items

Use `filter="startsWith"` for prefix matching. `keywords` add search aliases.
`textValue` supplies searchable plain text when an item has rich content.
`minLength` keeps the popup closed until the query is long enough.

Matching ignores case and repeated whitespace. It is not
diacritic-insensitive: `cafe` does not match `Café`.

## API reference

All parts accept `class` and `style`. They forward relevant native attributes
unless noted otherwise.

### Input

`Autocomplete.Input` renders the native text `<input>` and submitted control.
It accepts `placeholder`, `id`, `aria-label`, `aria-labelledby`, and relevant
native text-input attributes. `Root` owns `name`, `form`, `required`,
`disabled`, `readonly`, `autocomplete`, and the initial value.

### Clear

`Autocomplete.Clear` renders `<button type="button">`. Give it an accessible
name. It stays hidden while the input is empty. Its native `disabled` prop
permanently disables this action.

Duplicate values and identifiers are valid. Events report the selected item’s
metadata. Consumers that need a unique identity must author unique identifiers.

### Group and GroupLabel

`Autocomplete.Group` renders `role="group"`. Add one
`Autocomplete.GroupLabel` to every group. The label supplies the accessible
group name. The runtime hides a group when none of its items match.

### Separator

`Autocomplete.Separator` renders an accessibility-hidden separator. It does
not participate in keyboard navigation.

### Loading and Empty

`Autocomplete.Loading` and `Autocomplete.Empty` render disabled options.
Loading also contains a polite status region. `loading` replaces Empty and
sets `aria-busy` on Content.

## JavaScript API

The root exposes `value`, `disabled`, `readOnly`, `loading`, read-only `open`,
and `show()`, `hide()`, and `toggle(force?)`. Set these properties for runtime
state changes. Direct `value` assignment emits the non-cancellable value-change
event with reason `programmatic`; it does not emit native input or change
events.

`ormo:autocomplete-before-value-change` bubbles, crosses component boundaries,
and is cancellable. It runs before input, item, or clear changes. Its detail is
`{ value, previousValue, reason, identifier? }`.

`ormo:autocomplete-value-change` follows a completed value change. Item and
clear actions also dispatch native `input` and `change` events on the input.
`ormo:autocomplete-select` reports `{ value, identifier? }`.
`ormo:autocomplete-open-change` reports `{ open, reason }`. Open reasons include
`input`, `escape`, `outside`, `tab`, `selection`, and `programmatic`.

Child insertion and removal, item text, `value`, `textValue`, `keywords`, and
`disabled`, and root `loading`, `filter`, and `minLength` changes are observed.
Use root properties for `disabled`, `readOnly`, and `loading` so state changes
are atomic.

For Floating UI, load the adapter from a client script:

<script>
  import "@ormo/primitives/autocomplete/floating";
</script>`} />

## Accessibility and keyboard

Focus remains on `Autocomplete.Input`. `aria-activedescendant` identifies a
highlighted suggestion. Navigation clamps at the first and last enabled,
visible item. Pointer exit keeps the last pointer-highlighted item active.

## Styling

The primitive includes behaviour CSS only. Use `class` on each part for layout
and visual design. Public hooks are `data-state="open|closed"` on Root, Input,
and Content; `data-open` on Root and Content; `data-disabled` and
`data-readonly`; `data-highlighted` on Item; and `data-filtered` on Root.
Content receives `--ormo-autocomplete-trigger-width` and
`--ormo-autocomplete-trigger-height` while open.

## Runtime

Without JavaScript the native text input remains visible, valid, and
submittable. Suggestion content and custom actions stay hidden until the custom
element enhances them. Native Popover API support provides outside dismissal.
The fallback keeps the popup usable but does not reproduce equivalent outside
dismissal. Test that fallback if you support browsers without the Popover API.

## Accessible relationships

Use explicit <code>for</code>, <code>id</code>, and <code>aria-describedby</code> values when the relationships must be complete in the initial server-rendered HTML. Field preserves explicit relationships and fills in missing label, description, and error relationships when it connects.

Field owns a single native <code>input</code>, <code>select</code>, or <code>textarea</code>. Put one control in each <code>Field.Root</code>. Radio and checkbox groups need a dedicated group primitive.

<code>Field.Error</code> stays hidden in the server-rendered HTML unless
<code>match={true}</code>. The runtime reveals matching errors, exposes them
with <code>role="alert"</code>, and only adds visible errors to
<code>aria-describedby</code>.

## Anatomy

```astro
---
import * as Field from "@ormo/primitives/field";
---

<Field.Root>
  <Field.Label />
  <Field.Control />
  <Field.Description />
  <Field.Error />
</Field.Root>
```

You can replace <code>Field.Control</code> with [Input](/docs/components/input) or another native control. Prefer Field for labelling, descriptions, errors, and validation state.

## State

Field exposes <code>data-disabled</code>, <code>data-invalid</code>, <code>data-valid</code>, <code>data-validating</code>, <code>data-dirty</code>, <code>data-touched</code>, <code>data-filled</code>, and <code>data-focused</code> on its parts for consumer styling.

Listen for <code>ormo:state-change</code> when application code needs the complete state.

```js
field.addEventListener("ormo:state-change", (event) => {
  console.log(event.detail.state);
});
```

## Validation timing

Field validates on submit by default. Use <code>validationMode</code> to validate on blur or whenever the value changes. Debounce onChange validation with <code>validationDebounceTime</code>.

```astro
<Field.Root validationMode="onBlur">
  <!-- Field parts -->
</Field.Root>

<Field.Root validationMode="onChange" validationDebounceTime={300}>
  <!-- Field parts -->
</Field.Root>
```

## Error matching

Use <code>match</code> to display an error for a specific native <code>ValidityState</code> reason.

```astro
<Field.Error match="valueMissing"> Enter your email address. </Field.Error>

<Field.Error match="typeMismatch"> Enter a valid email address. </Field.Error>
```

Field supports <code>badInput</code>, <code>customError</code>, <code>patternMismatch</code>, <code>rangeOverflow</code>, <code>rangeUnderflow</code>, <code>stepMismatch</code>, <code>tooLong</code>, <code>tooShort</code>, <code>typeMismatch</code>, <code>valid</code>, and <code>valueMissing</code>.

## Browser API

Call <code>validate()</code> to validate immediately. Assign a sync or async <code>validator</code> in a browser script for custom rules.

```astro
<Field.Root id="account-email">
  <!-- Field parts -->
</Field.Root>

<script>
  import type { OrmoFieldElement } from "@ormo/primitives/field";

  const field = document.querySelector<OrmoFieldElement>("#account-email");

  if (field) {
    field.validator = async (value) =>
      value.endsWith("@example.com")
        ? null
        : "Use your example.com email address.";
  }
</script>
```

## Development toolbar

The [Ormo development toolbar](/docs/dev-toolbar) currently has no component-specific checks for Field. Supported Ormo primitives nested nearby or elsewhere on the page are still scanned. Continue to verify labels, descriptions, validation messages, and accessible state, and test the complete field with keyboard and screen-reader workflows.

## Anatomy

Import the parts and place one native control inside `Field.Root`. `Field.Control` renders an input; a native `<select>` or `<textarea>` can be used in its place.

Put native form attributes such as `name`, `required`, `disabled`, and `readonly` on the control. This preserves form submission and constraint validation in the server-rendered HTML, before the Field runtime loads.

<CodeBlock
  lang="astro"
  code={`---
import * as Field from "@ormo/primitives/field";
---

<Field.Root id="email-field" validationMode="onBlur">
  <Field.Label for="email">Email address</Field.Label>
  <Field.Control
    id="email"
    name="email"
    type="email"
    required
    autocomplete="email"
    aria-describedby="email-description"
  />
  <Field.Description id="email-description">
    We’ll only use this to contact you about your account.
  </Field.Description>
  <Field.Error match="valueMissing">
    Enter your email address.
  </Field.Error>
</Field.Root>`}
/>

`Field.Root` owns the first supported control in its subtree. Use one field per input, select, or textarea. For related native controls without coordinated state, use [Fieldset](/docs/components/fieldset). Wrap [CheckboxGroup](/docs/components/checkbox#checkbox-group) or [RadioGroup](/docs/components/radio#radio-group) in `Field.Root` when the group needs descriptions, errors, or Field state.

### Custom validation

Assign a synchronous or asynchronous validator through the browser API. Return a string to set native custom validity, or return `null` or `undefined` when the value is valid. The context includes a snapshot of the associated form data and an `AbortSignal`; pass the signal to cancellable work so stale validation stops when the value, validator, or owned control changes.

<CodeBlock
  lang="astro"
  code={`---
import * as Field from "@ormo/primitives/field";
---

<Field.Root
  id="username-field"
  validationMode="onChange"
  validationDebounceTime={250}
>
  <Field.Label>Username</Field.Label>
  <Field.Control name="username" required autocomplete="username" />
  <Field.Error>This username is not available.</Field.Error>
</Field.Root>

<script>
  import type { OrmoFieldElement } from "@ormo/primitives/field";

  const field = document.querySelector<OrmoFieldElement>("#username-field");

  if (field) {
    field.validator = async (value, _control, { formData, signal }) => {
      if (!value) return null;

      const organisation = formData?.get("organisation");
      const response = await fetch(
        \`/api/usernames/\${encodeURIComponent(value)}?organisation=\${organisation ?? ""}\`,
        { signal },
      );

      if (!response.ok) {
        throw new Error("Username validation failed");
      }

      const { available } = await response.json();
      return available ? null : "This username is not available.";
    };
  }
</script>`}

/>

A thrown error or rejected promise marks the field invalid and emits `ormo:field-validation-error`; it is not converted into a user-facing validation message. Handle the event when the interface needs a distinct service-failure message.

### Validation timing

`validationMode="onSubmit"` defers visible validity state until submission or an explicit `validate()` call. Use `"onBlur"` to validate after focus leaves the control, or `"onChange"` for validation while the value changes. `validationDebounceTime` only delays custom validation in `"onChange"` mode; native state and interaction hooks continue to update immediately.

### validator

The validator receives `(value, control, context)`. `context.formData` is a `FormData` snapshot or `null` when the control has no associated form, and `context.signal` is aborted when the result becomes stale. A string becomes the control’s native custom validity message; `null` or `undefined` clears it.

### ormo:field-state-change

Fires whenever the derived Field state changes after initial connection. It bubbles across shadow boundaries, cannot be cancelled, and exposes a `FieldState` snapshot as `event.detail.state`.

### ormo:field-validation-error

Fires when a validator throws or rejects. It bubbles across shadow boundaries, cannot be cancelled, and exposes `control`, `error`, and the validated `value` in `event.detail`. Aborted or stale validators do not emit it.

<CodeBlock
  lang="js"
  code={`const field = document.querySelector("ormo-field");

field.addEventListener("ormo:field-state-change", (event) => {
console.log(event.detail.state);
});

field.addEventListener("ormo:field-validation-error", (event) => {
console.error(event.detail.error);
});

const valid = await field.validate();`}
/>

## Accessibility

The field builds on native form semantics. `Field.Label` labels `Field.Control`, and the runtime connects descriptions plus visible errors through `aria-describedby`. Invalid state is mirrored to `aria-invalid`, while `Field.Error` uses `role="alert"` so newly revealed error text can be announced.

Every control needs an accessible name. Prefer a visible `Field.Label`; use `aria-label` or `aria-labelledby` only when visible label text is not appropriate. When marking a field required, include a visible text or symbol explanation that does not rely on colour alone. Keep instructions available before validation, and write errors that explain how to correct the value.

On unsuccessful form submission, Field focuses the first invalid owned control and uses the browser’s native validation interface when a native constraint also fails.

## Styling

Field ships no layout or brand styles. Add `class` to each rendered part and style native control state with pseudo-classes such as `:disabled`, `:required`, `:read-only`, `:valid`, and `:invalid`.

## Runtime

`Field.Root` loads one deduplicated custom-element runtime. Server rendering provides the native control, label relationship for `Field.Control`, authored descriptions, native form attributes, and explicit invalid state. Without JavaScript, native input focus, editing, submission, and constraint validation continue to work; automatic description and error relationships, validation timing, custom validators, derived state hooks, form-wide async validation, and the browser API are unavailable.

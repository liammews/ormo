## Default

Button renders a native <code>&lt;button type="button"&gt;</code>. Its text content provides the accessible name, and the native element supplies <kbd>Enter</kbd> and <kbd>Space</kbd> keyboard behavior. A default native Button ships no Button JavaScript in production.

</DemoBlock>

## Anatomy

Import the component and add a label:

<CodeBlock
  lang="astro"
  code={`---
import { Button } from "@ormo/primitives/button";
---

<Button>Save changes</Button>`}
/>

### Rendering links as buttons

The Button component should not be used as a link. `<button>` is for actions and always enforces button semantics. When a control looks like a button but navigates to another location, we recommend using a native <code>&lt;a href&gt;</code> and applying the same styles. This preserves the link semantics and browser behavior users expect.

## Examples

### Rendering a non-native button

Prefer the default native button whenever possible. When another element is required, set <code>as</code> to <code>"div"</code> or <code>"span"</code>. Button then supplies the button role, keyboard interaction, focusability, and disabled behavior that the element does not provide itself. Non-native rendering is inferred from <code>as</code>; <code>nativeButton={false}</code> remains accepted for explicitness.

</DemoBlock>

### Disabled

Set <code>disabled</code> when a button action is unavailable. The native attribute prevents pointer and keyboard activation, removes the button from the tab sequence, and exposes its disabled state to assistive technology. This path stays JavaScript-free for native buttons.

<DemoBlock code={buttonDisabledDemoCode}>
  <ButtonDisabledDemo />
</DemoBlock>

### Focusable when disabled

Use <code>focusableWhenDisabled</code> when an action becomes temporarily unavailable while it has focus, such as during submission. The button stays in the Tab sequence and exposes <code>aria-disabled="true"</code>, while Button suppresses pointer, keyboard, and form-submit activation.

This mode requires the Button runtime: native <code>disabled</code> cannot keep a control focusable, so Ormo omits that attribute and enforces the disabled contract in JavaScript. Without JavaScript, a focusable disabled button remains activatable.

<DemoBlock code={buttonFocusableDisabledDemoCode}>
  <ButtonFocusableDisabledDemo />
</DemoBlock>

### Pending

Set <code>pending</code> to expose <code>data-pending</code> for a loading indicator and <code>aria-busy="true"</code> for the busy state. Pending does not disable the button by itself. Combine it explicitly with <code>disabled</code> (and <code>focusableWhenDisabled</code> when focus must stay) when an in-progress action must not be repeated.

<DemoBlock code={buttonPendingDemoCode}>

</DemoBlock>

### Submit while focusable and disabled

With <code>type="submit"</code>, <code>disabled</code>, and <code>focusableWhenDisabled</code>, Button blocks direct activation and implicit form submission (for example <kbd>Enter</kbd> in a text field) once the runtime is loaded.

### Native forms and Astro Actions

Button defaults to <code>type="button"</code> to avoid accidental submissions. Set <code>type="submit"</code> deliberately inside a form, including a form backed by an Astro Action:

<CodeBlock
  lang="astro"
  code={`---
import { actions } from "astro:actions";
import { Button } from "@ormo/primitives/button";
---

<form method="POST" action={actions.saveProfile}>
  <!-- form fields -->
  <Button type="submit" name="intent" value="save">Save profile</Button>
</form>`}
/>

For a client-enhanced form, keep pending state in the form or island that owns the request. While it is pending, prevent duplicate submission with <code>disabled</code> (and <code>focusableWhenDisabled</code> when focus retention matters), and use <code>pending</code> on Button for <code>data-pending</code> styling plus <code>aria-busy</code>. Restore the state when an in-page request completes.

The optional <code>setButtonState</code> controller synchronizes these DOM states from a plain Astro script or any island framework. It persists <code>focusableWhenDisabled</code> on the element as <code>data-focusable-when-disabled</code>, so later <code>disabled</code> updates keep that mode without re-passing the flag. Importing the controller loads the interaction runtime:

<CodeBlock
  lang="ts"
  code={`import { setButtonState } from "@ormo/primitives/button";

const button = document.querySelector<HTMLButtonElement>("#save-profile");

if (button) {
${String.fromCharCode(32, 32)}setButtonState(button, {
${String.fromCharCode(32, 32, 32, 32)}pending: true,
${String.fromCharCode(32, 32, 32, 32)}disabled: true,
${String.fromCharCode(32, 32, 32, 32)}focusableWhenDisabled: true,
${String.fromCharCode(32, 32)}});

${String.fromCharCode(32, 32)}// After the in-page request settles:
${String.fromCharCode(32, 32)}setButtonState(button, { pending: false, disabled: false });
}`}
/>

Keep the visible label meaningful and use a nearby live region when completion or failure needs to be announced beyond <code>aria-busy</code>.

### Native button capabilities

Attributes not listed as component-specific props are forwarded to the native button. This includes form-owner attributes such as <code>form</code>, <code>formaction</code>, <code>formenctype</code>, <code>formmethod</code>, <code>formnovalidate</code>, and <code>formtarget</code>; submission data through <code>name</code> and <code>value</code>; popover control through <code>popovertarget</code> and <code>popovertargetaction</code>; and declarative commands through <code>command</code> and <code>commandfor</code>. Prefer these native platform features when they meet the interaction requirements, and check browser support for newer attributes.

## Accessibility

Use Button for an action such as saving, submitting, opening, or deleting. Use a native anchor instead when navigating to a URL. Give every button a concise accessible name through its text content, <code>aria-label</code>, or <code>aria-labelledby</code>. If the button contains only an icon, provide an accessible name and hide a decorative icon from assistive technology.

After activation, manage focus according to the action. For example, move focus into a dialog that opens, return it to the trigger when that dialog closes, and otherwise leave focus on the button unless the action creates a new context.

## Keyboard behavior

Native and non-native buttons activate with <kbd>Enter</kbd> or <kbd>Space</kbd>. They remain in the normal Tab sequence unless disabled. A disabled button remains in the sequence when <code>focusableWhenDisabled</code> is set.

## Styling

Every rendered element exposes <code>data-ormo-button</code>. Buttons expose <code>data-native-button="true|false"</code>, disabled buttons expose <code>data-disabled</code>, pending buttons expose <code>data-pending</code>, and focusable-disabled mode exposes <code>data-focusable-when-disabled</code>. These attributes keep state-based styling in CSS without a framework-specific callback API.

## Runtime and development checks

A native Button ships no Button JavaScript in production unless <code>focusableWhenDisabled</code> is enabled or <code>setButtonState</code> is imported by a client script. Non-native buttons load one deduplicated runtime for keyboard, disabled interaction, and submit guards. During development, Button also reports clear-cut accessibility mistakes in the console: a missing accessible name, a positive <code>tabindex</code>, a nested interactive control, or a mismatched <code>data-native-button</code> declaration. These checks are removed from production builds and complement rather than replace keyboard and screen-reader testing.

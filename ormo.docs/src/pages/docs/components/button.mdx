## Usage

Use `Button` for actions, such as submitting a form, opening a dialog, or changing the current interface. Do not use it for navigation.

When a link needs to appear as a button, render a native `<a href>` and apply matching button styles. This preserves link semantics and expected browser behaviour, including opening the destination in a new tab and copying its address.

## Anatomy

Import the component:

<CodeBlock

### Focusable when disabled

Add `focusableWhenDisabled` when keyboard and assistive-technology users need to reach a disabled control and discover why it is unavailable. After the runtime initialises, the button remains focusable but suppresses pointer, keyboard, programmatic click, and form-submit activation.

If JavaScript is unavailable, the control remains a native disabled button and is not focusable. This fail-closed behaviour prevents a disabled action from becoming temporarily active while the runtime loads.

### Non-native rendering

Use `as="div"` or `as="span"` only when a native `<button>` cannot be used. The component adds `role="button"`, focusability, <kbd>Enter</kbd> and <kbd>Space</kbd> activation, and disabled interaction guards. Non-native buttons do not submit or reset forms and require JavaScript for keyboard activation, so prefer the native default whenever possible.

## API reference

The component forwards the relevant native HTML attributes except where it owns an attribute’s semantics. Native rendering accepts button attributes; non-native rendering accepts div attributes and forces `role="button"`.

## Accessibility

Native rendering follows built-in HTML button semantics and browser keyboard behaviour. Give every `Button` an accessible name through visible text, `aria-label`, or `aria-labelledby`. Do not place links, buttons, form controls, or other focusable interactive content inside it, and avoid positive `tabindex` values.

Use non-native rendering only when native markup is genuinely unavailable. The component supplies button semantics and common keyboard behaviour, but it cannot provide native form submission, reset behaviour, or a complete no-JavaScript fallback for a `div` or `span`.

A consumer can cancel non-native keyboard activation with `event.preventDefault()`; stopping propagation alone does not cancel the button’s action. Moving focus away, disabling the button, or leaving the window cancels an unfinished <kbd>Space</kbd> press.

## Runtime

A standard native button, including ordinary disabled or server-rendered pending state, ships no button JavaScript in production. Non-native rendering and `focusableWhenDisabled` load one deduplicated runtime for keyboard activation, disabled interaction guards, form-submit protection, and post-navigation initialisation. Without JavaScript, native buttons retain browser behaviour, disabled native buttons remain safely disabled, and `focusableWhenDisabled` degrades to an ordinary non-focusable disabled button. Non-native buttons retain their static role, focus, and ARIA markup but lose synthesised keyboard activation and disabled interaction suppression.

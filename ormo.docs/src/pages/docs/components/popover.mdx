## Anatomy

Use a labelled dialog for rich, interactive content and include an explicit close control.

<CodeBlock lang="astro" code={`---
import * as Popover from "@ormo/primitives/popover";
---

<Popover.Root>
  <Popover.Trigger>Open filters</Popover.Trigger>
  <Popover.Content>
    <Popover.Title>Filters</Popover.Title>
    <Popover.Description>Narrow the results.</Popover.Description>
    <label>Keyword <input name="keyword" /></label>
    <Popover.Close>Done</Popover.Close>
  </Popover.Content>
</Popover.Root>`} />

## JavaScript API

The `<ormo-popover>` element exposes readonly `open`, mutable `finalFocus`, and `show()`, `hide(returnValue?)` and `toggle(force?)`. `ormo:popover-open-change` bubbles with `{ open, reason, returnValue }` after state changes.

<CodeBlock lang="js" code={`popover.addEventListener("ormo:popover-open-change", (event) => {
  console.log(event.detail.open, event.detail.reason);
});

popover.show();
popover.hide("saved");`} />

## Accessibility

Content uses a non-modal dialog pattern. `Popover.Title` and `Popover.Description` generate the accessible relationships; otherwise author `aria-label` or `aria-labelledby`. Focus enters the first suitable control and returns to the invoking trigger or `finalFocus`.

## Styling

Style consumer classes and public `data-state`, `data-open`, `data-side`, `data-align`, `data-starting-style` and `data-ending-style` hooks. Content exposes `--ormo-popover-side-offset`, `--ormo-popover-trigger-width` and `--ormo-popover-trigger-height`. Internal `data-ormo-popover-*` attributes are runtime selectors.

## Runtime

The server renders the trigger, labelled dialog content and requested placement. JavaScript coordinates native popover state, focus, dismissal, events and positioning; the optional floating entry registers Floating UI. Without JavaScript, the closed content remains in the DOM but cannot be opened.

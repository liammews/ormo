## Default

Popover opens a non-modal panel anchored to a button for rich interactive content such as filters or short forms. The rest of the page stays interactive. There is no focus trap and no page scroll lock.

Use Dialog when the task needs exclusive attention and an inert page. Use a future Tooltip or HoverCard for hover or focus-triggered content — Popover is click-triggered only.

</DemoBlock>

## Anatomy

Compose the trigger, anchored content, accessible name, optional description, and usually a Close control:

<CodeBlock
  lang="astro"
  code={`---
import * as Popover from "@ormo/primitives/popover";
---

<Popover.Root>
  <Popover.Trigger>Filters</Popover.Trigger>

  <Popover.Content side="bottom" align="start" sideOffset={8}>
    <Popover.Title>Filters</Popover.Title>
    <Popover.Description>
      Narrow the results by keyword.
    </Popover.Description>

    <!-- Forms and controls compose normally. -->
    <Popover.Close>Close</Popover.Close>

  </Popover.Content>
</Popover.Root>`}
/>

Content renders a <code>div</code> with <code>popover="auto"</code> and <code>role="dialog"</code>. Ormo generates IDs and connects Title and Description through <code>aria-labelledby</code> and <code>aria-describedby</code>. Opening uses the native Popover API. Default placement uses CSS Anchor Positioning.

Trigger always renders a native <code>&lt;button&gt;</code>. Put icons and labels in its slot — do not nest another button (including Ormo Button) inside Trigger.

CSS Anchor Positioning is the default. For Floating UI placement, install <code>@floating-ui/dom</code>, import the floating entry from a client <code>&lt;script&gt;</code> (so it never runs during Astro SSR), and set <code>positioning="floating"</code> on Root.

  lang="astro"

import * as Popover from "@ormo/primitives/popover";
---

<Popover.Root positioning="floating">
  <Popover.Trigger>Filters</Popover.Trigger>
  <Popover.Content side="bottom" sideOffset={8}>

Without the floating import, <code>positioning="floating"</code> warns in development and falls back to CSS anchors.

### Title

Provides the visible accessible name. Its <code>as</code> prop accepts <code>h1</code> through <code>h6</code> and defaults to <code>h2</code>.

### Description

Provides a concise description and defaults to <code>p</code>. It may render as <code>div</code>.

### Close

Renders an Ormo Button that closes Content. It accepts Button's native-button props, including <code>value</code>, which becomes the open-change <code>returnValue</code>.

Listen for <code>ormo:popover-open-change</code> on Root. It bubbles with <code>open</code>, <code>reason</code>, and <code>returnValue</code>. Reason is <code>trigger</code>, <code>close</code>, <code>escape</code>, <code>outside</code>, or <code>programmatic</code>.

There is no Astro <code>open</code> or <code>defaultOpen</code> prop. Open Popover with Trigger or <code>show()</code> after the custom element connects.

## Accessibility

Popover follows a non-modal dialog pattern: <code>role="dialog"</code> without <code>aria-modal</code>. Every Popover needs a concise accessible name. Prefer a visible Title.

Focus moves into Content on open (autofocus, first tabbable, or Content). Focus returns to the invoker or <code>finalFocus</code> on close. Tab is not trapped — users can leave Content into the page.

Do not use Popover as a Tooltip substitute. Hover and focus open with delay belong on Tooltip / HoverCard so WCAG 1.4.13 can be handled deliberately.

Development builds and the optional Ormo toolbar report missing or multiple Content parts, missing accessible names, invalid final-focus selectors, detached Triggers with invalid targets, and floating positioning without the floating import.

## Keyboard behavior

- <kbd>Enter</kbd> or <kbd>Space</kbd> on Trigger toggles Content.
- <kbd>Tab</kbd> and <kbd>Shift</kbd> + <kbd>Tab</kbd> move through focusable
  elements normally and may leave Content.
- <kbd>Escape</kbd> closes Content.
- Activating Close closes Content after consumer click handlers run.

## Styling

Pass your own <code>class</code> values to each part. Public state hooks are <code>data-state="open|closed"</code>, <code>data-open</code>, Content <code>data-side</code> / <code>data-align</code>, and brief <code>data-starting-style</code> / <code>data-ending-style</code> transition attributes. CSS custom properties include <code>--ormo-popover-side-offset</code>, <code>--ormo-popover-anchor</code>, and when measurable <code>--ormo-popover-trigger-width</code> / <code>--ormo-popover-trigger-height</code> (Floating UI path may also update left/top). Attributes prefixed with <code>data-ormo-\*</code> are internal runtime selectors.

Ormo ships only behaviour-critical CSS for CSS Anchor Positioning. Consumers own surface chrome, contrast, focus indicators, and motion.

## Runtime

Popover loads one Astro-processed, deduplicated runtime. The browser owns top-layer rendering and light dismiss for <code>popover="auto"</code>. Ormo connects parts, manages initial and final focus without trapping Tab, coordinates dismissal reasons and state, applies CSS Anchor hooks, and handles Astro client-router document swaps.

The Floating UI entry is separate: importing <code>@ormo/primitives/popover/floating</code> registers that engine. Pages that never import it never download Floating UI.

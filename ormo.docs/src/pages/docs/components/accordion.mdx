## Anatomy

Import the component and assemble its parts:

<CodeBlock
  lang="astro"
  code={`---
import * as Accordion from "@ormo/primitives/accordion";
---

<Accordion.Root>
  <Accordion.Item>
    <Accordion.Header>
      <Accordion.Trigger />
    </Accordion.Header>
    <Accordion.Content />
  </Accordion.Item>
</Accordion.Root>`}
/>

## Events

Listen for <code>ormo:value-change</code> on the root before the value changes. The event bubbles and crosses shadow boundaries. Changes from user interaction can be canceled with <code>preventDefault()</code>. A change that reveals a browser 'Find in Page' match is not cancelable, because the browser must be able to reveal the matched content.

Listen for <code>ormo:open-change</code> after an individual item opens or closes. Its detail contains the item’s <code>value</code> and new <code>open</code> state.

<CodeBlock
  lang="js"
  code={`accordion.addEventListener("ormo:value-change", (event) => {
  console.log(event.detail.value);
});

accordion.addEventListener("ormo:open-change", (event) => {
${String.fromCharCode(32, 32)}console.log(event.detail.value, event.detail.open);
});`}
/>

## Controlling value after render

Astro props configure the initial accordion item. After the page loads, read and write open state on the <code>ormo-accordion</code> element. Assigning <code>value</code> updates the items immediately. Listening for <code>ormo:value-change</code> and calling <code>preventDefault()</code> keeps the previous value, which is the controlled pattern for plain Astro scripts and islands.

<CodeBlock
  lang="astro"
  code={`---
import * as Accordion from "@ormo/primitives/accordion";
---

<Accordion.Root id="faq" defaultValue="delivery">
  <Accordion.Item value="delivery">
    <Accordion.Header>
      <Accordion.Trigger>Delivery</Accordion.Trigger>
    </Accordion.Header>
    <Accordion.Content>Delivery information</Accordion.Content>
  </Accordion.Item>
</Accordion.Root>

<script>
  const accordion = document.getElementById("faq");

  accordion?.addEventListener("ormo:value-change", (event) => {
    // Keep the previous value to fully control open state.
    // event.preventDefault();
    console.log(event.detail.value);
  });

  // Open a panel from application code:
  // accordion.value = "delivery";
</script>`}

/>

## Development toolbar

With the optional [Ormo development toolbar](/docs/dev-toolbar) enabled, Astro’s toolbar scans rendered Accordions and flags common composition mistakes:

- Roots with no Item parts
- Items missing a non-empty <code>value</code>
- Duplicate Item values in the same Accordion
- Items missing a Trigger or Content part
- Triggers without an accessible name

Select an issue in the toolbar to jump to the element. These checks catch structural mistakes during development; they do not replace keyboard and screen-reader testing.

Try the [Accordion toolbar demo](/docs/dev-toolbar/accordion-demo) for intentionally broken examples.

## Keyboard behavior

Every trigger is a native button in the normal Tab sequence. Use <kbd>Enter</kbd> or <kbd>Space</kbd> to toggle it.

## Styling

Item, Header, Trigger, and Content expose <code>data-open</code>, <code>data-disabled</code>, and <code>data-index</code>. Root exposes <code>data-disabled</code> and <code>data-orientation</code>. The existing <code>data-state="open|closed"</code> attribute remains available for explicit state selectors.

Content exposes <code>data-starting-style</code> and <code>data-ending-style</code> during transitions, along with <code>--ormo-accordion-content-height</code> and <code>--ormo-accordion-content-width</code>.
